# The computational biology ladder

Six hands-on projects that get harder on purpose. Everything through Level 5 runs on a laptop CPU in seconds, with synthetic data generated locally — no downloads, no GPU, no API keys. Each level tells you how to swap in real data and real models once your code works.

**The method:** every level ships a `starter.py` full of `TODO`s, a test suite you run until it's green, and a `solution.py` you read **afterwards**. Reading a solution before you've struggled with the problem feels like learning and isn't.

```bash
python data/make_data.py            # once — generates every dataset
python -m pytest level1_sequences   # red → green, that's the loop
python level1_sequences/solution.py # the demo, after your tests pass
```

## The ladder

| level | project | time | what's actually being taught |
|---|---|---|---|
| **1** | [Sequence toolkit](level1_sequences/) | 2–4 h | frames, strands, off-by-ones, edge cases |
| **2** | [Alignment from scratch](level2_alignment/) | 1–2 d | dynamic programming, affine gaps, and checking your own work |
| **3** | [ML on sequences](level3_ml/) | 2–4 d | leakage, confounds, proxy features — why your AUC is fake |
| **4** | [Structure & interfaces](level4_structure/) | 2–3 d | fixed-column parsing, contact maps, superposition, chirality |
| **5** | [A binder-design campaign](level5_pipeline/) | 1–2 w | funnels, backend interfaces, provenance, filter ordering |
| **6** | [Capstone](level6_capstone/) | 3–6 w | choosing a question and defending an answer |

Do them in order. Level 4 uses Level 2; Level 5 uses Levels 3 and 4; Level 6 uses everything.

## The three ideas the whole ladder is built around

**1. Check your work with something that doesn't share code with it.** Level 2's `score_alignment` re-scores what the DP produced. If they disagree, there's a bug — and there always is at first. Every later level has its own version of this referee.

**2. The number that looks best is usually the one that's wrong.** Level 3's dataset is booby-trapped four ways, and the leaky split scores 0.841 against the honest split's 0.708. Both are real outputs of real code. Only one is a result.

**3. A mock model is not a small real model.** Level 5's pipeline runs in 0.3 seconds with fake backends. It proves your plumbing works and says nothing about whether a design binds. Knowing which of those you've demonstrated is most of the job.

## Setup

```bash
python -m pip install numpy pandas scikit-learn matplotlib pytest
python data/make_data.py
python -m pytest -q                    # runs every level's tests
bash run_all.sh                        # runs every demo, writes figures/
```

Python 3.9+. No Biopython anywhere — Levels 1, 2 and 4 are the things Biopython would have done for you, and doing them once is the point. Install it afterwards and use it happily.

## About the data

Every dataset in `data/` is generated by `data/make_data.py` and is **synthetic**:

- deterministic — same seed, same files, so a failing test is reproducible
- ground truth is known — you can tell whether your code is right, not just whether it runs
- the traps are planted — a motif, near-duplicate families, a batch confound, label noise

Synthetic data is a sandbox, not a substitute. Each level's README ends with how to point the same code at real data (NCBI genomes, RCSB structures, SKEMPI, a real screening set), and what will break when you do. **Things breaking on real data is the curriculum, not a detour.**

## Figures

Each demo writes to `figures/`:

- `level2_dotplot.png` — a dot plot where the shared domain is the diagonal streak
- `level3_roc.png` — the same model under a leaky and an honest split

## A note on what this is for

Finishing all six levels does not make you a computational biologist; it gives you the habits that make the next real project survive contact with a reviewer. The parts that transfer are the referee, the honest split, and the manifest — not the specific algorithms, which you will mostly import from now on.
